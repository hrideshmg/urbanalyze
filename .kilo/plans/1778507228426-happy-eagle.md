# Plan: Addressing API Rate Limits and Timeouts

## Current Status
- The application is frequently hitting `429 (Too Many Requests)` errors on Gemini API, indicating the current concurrency handling is insufficient.
- The application is hitting `504 (Gateway Timeout)` errors on Overpass API, indicating query performance or API load issues.

## Strategy
### 1. Robust API Caching
- **Implementation**: Introduce an in-memory caching layer (or persistent, if suitable) for API calls (Gemini, Overpass, Pexels, etc.).
- **Benefit**: Redundant requests (same location/prompt) will be served instantly, reducing API load.

### 2. Concurrency Control (Throttling)
- **Implementation**: Replace ad-hoc delays (`await delay(index * 2000)`) with a formal concurrency-limiting utility (e.g., `p-limit` or a simple semaphore-based queue) to manage concurrent outgoing API calls.
- **Benefit**: Ensures we stay within rate limits dynamically rather than relying on fixed delays.

### 3. Overpass API Optimization
- **Implementation**: 
    - Review and restrict search radius in Overpass queries.
    - Implement a timeout/retry wrapper specifically for Overpass requests (different from Gemini).
    - If a specific area fails, try a smaller bounding box as a fallback.

### 4. Graceful Degradation
- **Implementation**:
    - If an API call fails after retries, return "mock/safe" data instead of crashing or breaking the UI.
    - Ensure the UI conveys this status to the user (e.g., "Summary generation limited - showing partial data").

## Execution Steps
1.  **Analyze**: Review `app/_scripts/integrations.js` and `components/search_elements/search_form.jsx` for existing API call patterns.
2.  **Setup Caching**: Write a generic cache wrapper.
3.  **Setup Concurrency**: Write a request queue utility.
4.  **Refactor**: Apply the new utilities to `getNearbySettlements`, `getHospital`, `geminiSummarise`, and `geminiGenerateWeights`.
5.  **Verify**: Test search performance and error handling under load.
